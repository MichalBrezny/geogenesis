# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Geogenesis: a planet simulation** — a browser-based planet simulation game in the style of SimEarth (Maxis, 1990): geosphere, atmosphere, biosphere and civilization models coupled by Gaia-style feedback loops. Stack: TypeScript (strict), Vite, React for UI, Canvas 2D for the map, Vitest.

All code, identifiers, comments, commit messages and UI strings are in **English** (international audience). The project owner may write in Czech.

## Commands

```sh
npm run dev          # dev server at http://localhost:5173 (polling watcher; if the UI looks stale, restart it)
npm test             # all tests once (vitest run)
npx vitest run src/sim/core/grid.test.ts   # single test file
npx vitest run -t "wraps east-west"        # single test by name
npm run test:watch
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
npm run format       # prettier --write
npm run build        # typecheck + production build
```

## Architecture

```
src/sim/      pure simulation core (no DOM, React or render imports — enforced by ESLint)
  core/       grid, fields, planet state, seeded RNG, component interface
  models/     geosphere/, atmosphere/ (later biosphere/, civilization/)
  simulation.ts  orchestrator; world.ts  assembles planet + component pipeline
src/render/   draws planet fields to a canvas (palettes, layers)
src/worker/   simulation Web Worker: SimHost (testable logic), message protocol
src/ui/       React UI
src/i18n/     UI strings (en.json); always use t('key') for user-visible text
```

Key design decisions:

- **Landlab-style fields and components.** Per-cell data lives in `PlanetState.fields`: one typed array (`Float32Array` or `Int32Array`) per named field; add new fields to `FIELD_SPECS` in `src/sim/core/fields.ts` with type and unit. Processes implement `SimComponent` (`src/sim/core/component.ts`): they declare `inputs`/`outputs` fields and implement `runOneStep(state, dtYears, rng)`. `createSimulation` validates that every input is initialized or written by an earlier component, so component order matters: geosphere → atmosphere → biosphere → civilization → events.
- **Multiple time scales.** Slow components set `minIntervalYears`; the orchestrator skips them until enough time has passed and then passes the accumulated elapsed years as `dt`. Every component runs on the first step.
- **Grid.** Equirectangular lat/long grid, row-major (`y * width + x`), row 0 = north, wraps east-west, no wrap at the poles (neighbour = -1). Cells are not equal: east-west spacing (`rowDx`) and area (`rowCellArea`) shrink towards the poles, so use real distances/areas and `areaWeightedMean` for global statistics. `getTopology(grid)` gives cached 8-neighbour tables and distances. Resolution is a parameter (UI offers 128×64, 256×128 default, 512×256). Never hard-code grid dimensions. The grid radius comes from `planetParams.radius`; nothing may assume Earth's radius. Per-cell constants tuned on the 128×64 reference grid must be scaled with `resolutionScale(grid)` or expressed in physical units (metres, m²) so behaviour does not change with resolution; verify by comparing 1 Gyr runs at two resolutions.
- **Determinism.** All randomness goes through `Rng` (`src/sim/core/rng.ts`), and its state is stored in `PlanetState.rngState`. The same seed must reproduce the same planet and history; don't use `Math.random()` inside `src/sim`.
- **Plain-data state.** `PlanetState` must stay serializable (typed arrays and plain objects, no class instances or closures), so it can be saved and moved into a Web Worker later.
- **Geosphere pipeline** (`src/sim/world.ts`): `generateTectonicPlanet` builds plates (noise-warped Voronoi with Euler-pole velocities), continental crust, boundary relief and the `upliftRate` field; each step then runs `plateDrift` → `tectonicUplift` → `flowRouting` (priority-flood depression filling + D8 + drainage area; runoff from the last step's precipitation via the Budyko curve, summed downstream into `discharge`) → `streamPowerEroder` (implicit Braun–Willett / Landlab FastscapeEroder, n = 1, driven by discharge / `REFERENCE_RUNOFF` as an effective area, so wet mountains erode faster than deserts) → `linearDiffuser` (finite-volume, land only, auto sub-stepping). Sea level is `SEA_LEVEL` = 0; ocean cells are flow outlets. Eroded material is removed, not deposited.
- **Plate drift** (`drift.ts`, `plates.ts`): each `Plate` stores its crust in its own reference raster (`plate.crust`, same grid as the planet) plus a cumulative `rotation` matrix. Each step the plates rotate and the planet fields (`plateId`, `elevation`, `crustType`) are re-composed by gathering from the rasters (plates are culled per cell by a bounding cap); before that, the previous step's field changes are written back as averaged deltas, because several planet cells can sample one reference cell. Crust created by hole filling never displaces another plate's crust, otherwise fill/consume cycles create runaway mountains. Never resample plate shapes from the planet grid — that is what made plates fragment in earlier attempts. Generation removes warped-Voronoi exclaves. Every 5 Myr of plate time, detached terranes below 200,000 km² move between the plates' reference rasters, larger detached continents rift into stable new plate ids (at most four daughter slots), and undersized plates merge into their largest neighbour. Overlaps: continental beats oceanic, colliding continents thicken (spread over neighbours) and stall; gaps become ridge-depth ocean floor. Continental crust is kept near a target fraction by arc and shelf accretion; the target grows with age (`continentalCrustTarget`: ~6% at 0.5 Gyr, near the 30% ceiling by ~2.5 Gyr), and plate speeds follow `mantleHeat` (≈1.8× today on a young planet), so young planets are island worlds with fast plates. If you change fields that belong to crust, make sure the write-back carries them into the plates.
- **Planets and stars** (`PlanetState.planetParams` in `src/sim/core/planet.ts`; `star.ts`; `src/sim/models/planetary.ts`): radius, surface gravity (default from Earth density, ∝ radius), orbital distance, star type G/K/M/F, rotation period (negative = retrograde), moon, tidal locking, initial water/N₂/CO₂, crustal carbon, tectonic regime and dynamo strength; omitted values inherit the Earth calibration. Star luminosity ∝ M⁴ with Gough's brightening scaled to the star's lifetime (`starProperties`); XUV and stellar wind ∝ luminosity/d² with an activity boost decaying over the star's active years (M 2 Gyr, K 0.5, others 0.1). Tidal locking is automatic for M stars at ≤ 0.2 AU: per-cell substellar insolation, no seasons, `LOCKED_HEAT_TRANSPORT`. Without a moon, obliquity random-walks deterministically (Laskar; fixed 10 Myr boundaries with their own seeded Rng, so step length does not matter), except slow rotators (> 1000 h) and locked planets. Mantle heat ∝ radius; the magnetic field fades as the core cools (lifetime ∝ radius⁴); `planetaryEvolution` records `magneticFieldLost`, `stagnantLid` and `atmosphereLost`. Tectonic regime is mobile or stagnant: mobile turns stagnant irreversibly when mantle heat drops below 0.7 or the ocean is lost; stagnant means no plate drift or uplift, plume volcanism only.
- **Climate** (`src/sim/models/atmosphere/`): `stellarEvolution` sets `globals.solarInput` from the planet age (faint young Sun; random planets start at 0.5, 2 or 4 Gyr, see Start options). `createClimate` is a 2D energy-balance model (Budyko–Sellers/North) on a coarse 64×32 grid with an ice–albedo feedback. Its low-temperature OLR keeps the calibrated North A + B·T fit, but a wet atmosphere bends smoothly towards the 294 W/m² Simpson–Nakajima limit above 40 °C; absorbed flux above the limit has no wet steady state, while a dry planet returns to linear OLR. Greenhouse forcing includes CO₂, CH₄ and explicit water vapour; CO₂/H₂O bands broaden as (surface pressure / Earth pressure)^0.5, with CO₂ counting only above 1 bar (its self-broadening below that is in the forcing fit), so an O₂-free young atmosphere needs ~0.5 bar CO₂; wet planets keep CO₂ below a 3-bar guardrail. Meridional diffusivity scales as pressure^0.7, and temperatures are bounded to −120…700 °C. The lapse rate scales with gravity; its datum is the sea surface only while the ocean covers ≥ 20 % of the planet, otherwise the area-mean surface. `THIN_ATMOSPHERE_COOLING` (40 W/m², faded in below 0.1 bar) removes the greenhouse built into the North OLR fit that a near-vacuum lacks (Mars lands near −60 °C). `heatTransportScale` = P^0.7 above 0.1 bar, linear in P below, floor 0.002, clamp 80, times a rotation scaling and `LOCKED_HEAT_TRANSPORT` (2.5) when locked. Hot dry CO₂ atmospheres get a sulfur-cloud/haze albedo (up to 0.75, Venus); clouds need water vapour (`CLOUD_VAPOR_SHARE`); runaway greenhouse needs water. In short steps temperatures approach equilibrium over `OCEAN_RESPONSE_TIME` (40 years).
- **Atmosphere and water.** `atmosphere.co2` and `ch4` are partial pressures in microbar (the familiar Earth values remain numerically ppm); `n2`, inert gas and `waterVapor` are in bar, while `o2` remains a volume fraction and its partial pressure is derived. `globals.surfacePressure` is their total; bar↔column mass conversions use the planet's gravity. `globals.water` is the conserved extant inventory in metres GEL; runaway steam escapes as hydrogen at an age/XUV- and cold-trap-dependent rate, escaped oxygen oxidises the crust, and `runawayGreenhouse` / `oceansLost` are recorded once. Cold low-gravity worlds also lose hydrogen by Jeans-like escape (`JEANS_COLUMN_RATE`). Non-water gases are removed by stellar-wind sputtering (`SPUTTERING_RATE`, shielded by the magnetic field, scaled by wind and gravity), integrated exactly (constant above 1 bar, exponential below) so step length does not matter; inventories stay conserved and escaped amounts are recorded (`escapedAtmosphere`, `escapedWater`).
- **Seasons** (`src/sim/models/atmosphere/seasons.ts`): `controls.obliquity` sets axial tilt. The climate integrates daily-mean insolation over a circular orbit and diagnoses `seasonalAmplitude` from the analytic linear response of land or an ocean mixed layer to its first annual harmonic; land and ocean responses are mixed by continentality, 1 − exp(−distance to the sea / 1,000 km), so coasts stay maritime and interiors swing widely. Glaciers use positive degree days and seasonal snowfall, surface ice is weighted toward sunlit months, and biome treelines use warmest/coldest monthly means. This remains a steady-state diagnostic, not a time-stepped seasonal EBM.
- **Circulation and precipitation** (`circulation.ts`, `precipitation.ts`, on the shared 64×32 `atmosphereGrid`): a three-cell circulation (Hadley/Ferrel/polar) gives the surface wind fields `windU`/`windV`; the ITCZ follows the thermal equator column by column and the Hadley width grows with the equator–pole contrast and for slow rotators; beyond ~60° (blended from 45°) it becomes a single cell per hemisphere, and a retrograde rotation mirrors the zonal winds. The pressure map stays a 1013 hPa anomaly field (absolute pressure is `globals.surfacePressure`). Precipitation is a steady-state moisture budget carried by those winds (semi-Lagrangian, 150 pseudo-steps): evaporation from the sea towards a Clausius–Clapeyron humidity, recycling over land (more with plants), rain rate raised by converging and upslope air and lowered by sinking air, plus rain-out above saturation; the coarse result is shifted towards fine windward slopes within each coarse cell. Calibrate with zonal means (ITCZ wet, subtropics dry, mid-latitudes wetter, poles dry) and the desert share of land, at two resolutions.
- **Ocean** (`ocean.ts`, same atmosphere grid): wind-driven gyres after Stommel — Sverdrup interior integrated westward from each basin's east coast, closed by a western boundary layer; basins that nearly circle the planet lose their gyres (circumpolar flow); a small zonal wind drift. Ekman divergence gives upwelling (equator, eastern coasts). The sea surface anomaly (`oceanAnomaly`) = currents across the zonal-mean temperature gradient of the background state (climate temperature minus last anomaly, so it cannot feed on itself and drift) + upwelling cooling, net heat removed, faded towards the poles, spilled onto coasts; the climate adds it to temperatures (so cold currents also dry coasts through lower evaporation).
- **Carbon cycle** (`carbon.ts`): the silicate-weathering thermostat. Outgassing is the area-weighted integral of `volcanicActivity` times mantle heat and the volcanism control; the activity field is normalized to retain the modern 30% hotspot / 70% plate-speed calibration. Organic carbon burial (`MODERN_BURIAL`, 20% of the flux for a modern biosphere, scaled by photosynthesis) is an extra sink; seafloor weathering (`SEAFLOOR_SHARE` 8%) gives water worlds a thermostat; land weathering grows with runoff, temperature (≈9%/°C) and CO₂ and stops under ice. Both weathering sinks stop without liquid water, after which outgassing can build CO₂ through the full 100-bar representable range (`MAX_CO2 = 1e8` microbar). CO₂ is solved implicitly each step; wet worlds retain the former 1-bar natural solve guardrail so raising the representable maximum does not change Earth calibration. Outgassing draws on a finite crustal carbon reservoir (`globals.crustalCarbon`, default 80 bar × (g/g⊕)²): dry or sinkless worlds degas it first-order over `DRY_DEGASSING_TIME` (300 Myr) and the wet solve is booked against it. `createRandomWorld` spins the atmosphere up before the first step (`spinUpAtmosphere` damps CO₂ updates in log space when the first guess is a snowball). Expected behaviour: CO₂ falls as the star brightens, then a runaway begins near 7 Gyr and ocean loss leaves a hot, dry, CO₂-rich planet.
- **Volcanism** (`volcanism.ts`): `volcanicActivity` combines convergent arcs, divergent ridges and continental rifts with 10–20 long-lived mantle-frame hotspots. Hotspots build moving-plate island chains in metres/year while old oceanic edifices subside. Seeded eruption rates are per year; geological steps aggregate ordinary activity, short steps resolve transient one-year aerosol forcing, and rare large igneous provinces add an extra outgassing flux (`globals.lipOutgassing`, 1.5× modern) for about 1 Myr — a flux, not a CO₂ pulse, so the implicit carbon solve answers it the same at any step length (+2–5 °C) — and record a located event.
- **Impacts and start options** (`impacts.ts`, `PLANET_STARTS` in `world.ts`): a late heavy bombardment, Poisson impacts per step from a flux decaying over 150 Myr plus a small background, with power-law sizes; craters go through the drift write-back, comets add a little water, big impacts heat the climate briefly (`globals.impactHeating`) and sterilise life locally or, early on, globally. New random planets start **young** (0.5 Gyr, no life, CO₂-rich, few continents), **microbial** (2 Gyr, prokaryotes) or **quick** (4 Gyr, the pre-M11 pace via `evolutionTimeFactors`); the choice is part of the saved `RandomWorldSettings`. A young start's geological era lasts a few hundred 10 Myr steps.
- **Surface albedo and life.** `createSurfaceAlbedo` sets the ice-free `surfaceAlbedo` field (ocean, land, daisies); the climate model mixes it with ice. Biosphere components change albedo through the fields this component reads.
- **Biomes** (`src/sim/models/biosphere/biomes.ts`, data in `src/sim/data/biomes.ts`): a Whittaker-style classification from annual temperature and precipitation, plus ice, alpine rock and river swamps. Biome data sets surface albedo and a weathering multiplier, so vegetation feeds back on climate and CO₂. Tune biome properties in the data table, not in the models.
- **Sea level, aridity and lakes.** `globals.seaLevel` is found by bisection over the real-area elevation field so basin volume equals liquid `globals.water` after subtracting grounded land ice and atmospheric vapour (10 kyr relaxation). Generated planets initialize the inventory to reproduce the 0 m ice-free datum; a uniform `seaLevelDatum` re-referencing prevents plate-raster resampling from moving that arbitrary datum, without changing relief or capacity. Low-water worlds fill only their deepest basins and zero liquid water yields no ocean cells. Land vs ocean is always tested against `globals.seaLevel`. Biomes use P/PET aridity; significant closed depressions hold freshwater or endorheic salt lakes/flats and terminate the river network.
- **Glaciers, sediments and clouds.** Land ice is `iceThickness` from a snow mass balance (snowfall − melt − sublimation, exponential approach to a sheet thickness set by the ice extent; `ice.ts`); land `iceCover` = glacier cover from thickness plus snow cover on the thermal ramp limited by snowfall, so polar deserts can stay bare; sea ice stays thermal. The stream power eroder adds warm-based glacial erosion (fjords to 500 m below sea level) and routes the eroded volume downstream: deposition where carrying capacity (C·Q·S) falls short, filled depressions, then shelf/delta deposits within ~500 km of the mouth (mass conserved; any remainder in `globals.sedimentExport`). Land ice is limited by the water inventory (`limitIceToInventory`), and cold-trapped ice is kept without a sea. `cloudModel` (`clouds.ts`) diagnoses high cloud from rain and low cloud from cold seas / land humidity; the climate adds `LOW_CLOUD_ALBEDO` × (low cloud − `REFERENCE_LOW_CLOUD`) to the albedo of planets that run it (Earth-like mean total cover ≈ 0.6).
- **Life** (`src/sim/models/biosphere/life.ts`, classes in `src/sim/data/lifeClasses.ts`): `PlanetState.biota.populations` holds a population (0..1 of carrying capacity) per class per cell. Each step populations relax to their suitability (habitat, temperature, O₂, plants for land animals) where present, and colonise adjacent habitable cells at `DISPERSAL_SPEED` (300 km/Myr) through the shared `disperse` front model (`src/sim/models/dispersal.ts`), so spreading does not depend on the step length or the grid and life cannot cross unsuitable terrain. Missing classes evolve from a living ancestor with a chance set by how much of their potential habitat the ancestor occupies (`BASE_EVOLUTION_TIME`, `difficulty`). Plants (`vegetation` field) green the biomes and speed weathering. `biogeochemistry` derives O₂ from photosynthesis (with a sink that makes a Great Oxidation Event; the sink is large on a young, reduced planet and fades with age, `oxygenSink`, so oxidation comes at ~2.3–2.5 Gyr) and CH₄ from anoxic microbes. Per-class `evolutionTime` multipliers (data) make the first steps slow: eukaryotes ~1.2 Gyr, plants and radiates ~1–2 Gyr, later classes at the base pace. On a lifeless planet prokaryotes arise by chance (abiogenesis) in liquid, ice-free sea near volcanic vents, suppressed after big impacts, and can arise again after a sterilisation.
- **Civilization** (`src/sim/models/civilization/`, ages in `src/sim/data/civilization.ts`): established animals may become sentient (weighted by `SENTIENCE_POTENTIAL` and the share of their habitat they fill). The civilization settles where its species lives and food allows, spreads at its age's `spreadSpeed` through `disperse` (over narrow seas, `SEA_CROSSING` in metres, once seafaring), clears vegetation, emits CO₂ from the Industrial Age, suffers plagues and nuclear wars, and advances through `TECH_AGES`; finishing Nanotech is Exodus. `PlanetState.events` logs notable moments (`recordEvent`).
- **Eras and time scales** (`src/sim/eras.ts`, after SimEarth): `planetEra` is geological while only microbes live (10 Myr steps), evolution once complex life exists (500 kyr), civilization from sentience and technology from the Industrial Age (the age's `yearsPerStep`, down to 5 years); after an Exodus or collapse it falls back to evolution. `World.stepYears` is `eraStepYears`; `eraTracker` stores `globals.era` and logs `eraReached`. Every model must therefore give the same results whatever the step length: use rates × dt, exponential relaxation or implicit solves, never "one cell per step". Slow components are wrapped with `withMinInterval` (geology 100 kyr, evolution 10 kyr, history 1 Myr) so they cost nothing in short steps; components receive the elapsed time as `dt`.
- **Player controls and tools.** `PlanetState.controls` holds runtime multipliers (sun, volcanism, drift, erosion, mutation) that components read every step — use them instead of component options for anything the player may change. Tools (`src/sim/tools/tools.ts`) are pure functions on the state with an Ω cost (`globals.energy`, income from `energyIncome`, `unlimitedEnergy` for experimental mode); terrain edits reach the plates through the drift write-back.
- **Save files** (`src/sim/serialize.ts`): the whole `PlanetState` plus scenario id, as a binary file (magic, `SAVE_VERSION`, JSON header with typed arrays referenced into an aligned data section), gzip-compressed in the worker. Anything added to `PlanetState` is saved automatically if it is plain data or a supported typed array; bump `SAVE_VERSION` when the shape changes incompatibly. Each scenario provides `restore(planet)` that rebuilds its simulation without regenerating; component schedules live in `PlanetState.lastRunYear` so a loaded game resumes identically.
- **Scenarios** (`src/sim/scenarios/`): `SCENARIOS` maps ids to world factories (`random` = `createRandomWorld`, `daisyworld`, `aquarium` = a random planet with no continents, `mars` and `venus` = `createPlanetPreset`: present day 4.5 Gyr, stagnant lid, no magnetic field, Mars with a 0.05 bar carbon reservoir). Custom planet parameters are chosen in the new-planet menu, and the Planet panel (`PlanetPanel.tsx`) shows them. Each `World` carries its own `yearsPerStep`. Daisyworld is land-only with no geology or carbon cycle and no ice–albedo feedback; daisies (Watson & Lovelock 1983) run many generations per step, relax towards the result and disperse to neighbours. The UI picks charts and the initial map layer per scenario (`SCENARIO_VIEW` in `App.tsx`).
- **History** (`src/sim/history.ts`): `recordHistory` samples global series each step into `PlanetState.history` (thinned past 2000 samples); frames carry it to the small-multiple uPlot charts (`src/ui/charts`). One measure per chart — no dual axes.
- **Tuning.** Erodibility and uplift are effective values for ~300 km cells, not field measurements, and are tuned as a pair: their ratio sets equilibrium mountain height, their magnitude sets how fast landscapes evolve. Check changes over ~1 Gyr of 1 Myr steps (land fraction, mean land elevation, peak height), not just one step.
- **UI layout** (`src/ui`): `TopBar` (time controls, vital signs, planet menu), a left sidebar of `Collapsible` panels (tools, model controls), the stage (`LayerBar`, `PlanetView` = flat map or optional globe with the cell inspector, `MapLegend`) and a right `TabbedPanel` (history, life, civilization). `SCENARIO_VIEW` in `App.tsx` sets each scenario's layers and charts; keyboard shortcuts live in `App.tsx` via `useShortcuts`. Every control gets a `title` hint from the strings. UI icons are inline SVG in `icons.tsx` (currentColor); the app icon is in `public/`. Wind and current overlays (`OVERLAYS` in `PlanetView.tsx`) are animated particles in latitude/longitude (`render/particles.ts`, windy.com style) drawn through the map or globe projection on a screen-resolution canvas; with prefers-reduced-motion they fall back to static arrows (`render/arrows.ts`).
- **Worker.** The simulation runs in a Web Worker (`src/worker/sim.worker.ts` → `SimHost`). The UI sends `WorkerRequest`s and receives `Frame`s: transferred copies of the fields in `RENDERED_FIELDS` plus stats. A field the map needs must be added to `RENDERED_FIELDS`.
- **Performance.** `simulation.timings` gives per-component milliseconds for the last step (shown as "Step: N ms" in the UI). Measure before optimizing. Approximate step costs on a young planet: 128×64 ≈ 27 ms, 256×128 ≈ 70 ms; `plateDrift` dominates. The life model only works on classes that exist or can evolve, and the carbon cycle sums weathering once per step — keep hot loops away from absent classes and per-iteration planet sweeps.

## Roadmap

M0 scaffold (done) → M1 geosphere (done: plate-based terrain, drift, uplift, flow routing, fluvial erosion, diffusion; deliberately not doing more Landlab-style physics such as flexure or sediment transport until gameplay needs it) → M2 climate (done: energy balance, ice–albedo, precipitation, carbon cycle, history charts, Daisyworld) → M3 biomes (done) → M4 life classes and evolution (done) → M5 civilization (done) → M6 player tools, Ω energy budget, scenarios (done: tools, controls, save/load) → M7 presentation (done = alpha 0.1, tag v0.1.0-alpha: optional globe view `src/render/globe.ts`, CI and GitHub Pages workflows in `.github/workflows`, README with a single milestone table — keep it up to date). Roadmap (detailed in README; physical core first, game layers once it is tuned): M8 interface (done = alpha 0.2) → M9 Earth system (done: eras, circulation, ocean, glaciers, clouds, seasons) → M10 plates and volcanism (done) → M11 young planet (done: origin of life, bombardment, growing continents) → M12 atmosphere and planets (done: M12a pressure, water vapour, runaway greenhouse, water inventory; M12b planet parameters, stars, rotation, tidal locking, magnetic field, escape, stagnant lid, Mars/Venus presets) → M13 turning points of life (Cambrian explosion, mass extinctions) → M14 goals (Mars, Venus, snowball scenarios) → M15 challenge → M16 graphics (icons for events, tools, layers and charts; better charts; menus; Walter–Lieth climate diagrams; life and city icon overlays on the map) → M17 feedback → M18 onboarding and balance; each milestone is a minor release.
