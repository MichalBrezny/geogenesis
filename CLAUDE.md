# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Geogenesis: a planet simulation** — a browser-based planet simulation game in the style of SimEarth (Maxis, 1990): geosphere, atmosphere, biosphere and civilization models coupled by Gaia-style feedback loops. Stack: TypeScript (strict), Vite, React for UI, Canvas 2D for the map, Vitest.

All code, identifiers, comments, commit messages and UI strings are in **English** (international audience). The project owner may write in Czech.

## Commands

```sh
npm run dev          # dev server at http://localhost:5173 (polling watcher; if the UI looks stale, restart it)
npm test             # all tests once (vitest run)
npx vitest run src/sim/core/grid.test.ts   # single test file
npx vitest run -t "wraps east-west"        # single test by name
npm run test:watch
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
npm run format       # prettier --write
npm run build        # typecheck + production build
```

## Architecture

```
src/sim/      pure simulation core (no DOM, React or render imports — enforced by ESLint)
  core/       grid, fields, planet state, seeded RNG, component interface
  models/     geosphere/, atmosphere/ (later biosphere/, civilization/)
  simulation.ts  orchestrator; world.ts  assembles planet + component pipeline
src/render/   draws planet fields to a canvas (palettes, layers)
src/worker/   simulation Web Worker: SimHost (testable logic), message protocol
src/ui/       React UI
src/i18n/     UI strings (en.json, cs.json) and locale selection; always use t('key') for user-visible text
```

Key design decisions:

- **Landlab-style fields and components.** Per-cell data lives in `PlanetState.fields`: one typed array (`Float32Array` or `Int32Array`) per named field; add new fields to `FIELD_SPECS` in `src/sim/core/fields.ts` with type and unit. Processes implement `SimComponent` (`src/sim/core/component.ts`): they declare `inputs`/`outputs` fields and implement `runOneStep(state, dtYears, rng)`. `createSimulation` validates that every input is initialized or written by an earlier component, so component order matters: geosphere → atmosphere → biosphere → civilization → events.
- **Multiple time scales.** Slow components set `minIntervalYears`; the orchestrator skips them until enough time has passed and then passes the accumulated elapsed years as `dt`. Every component runs on the first step.
- **Grid.** Equirectangular lat/long grid, row-major (`y * width + x`), row 0 = north, wraps east-west, no wrap at the poles (neighbour = -1). Cells are not equal: east-west spacing (`rowDx`) and area (`rowCellArea`) shrink towards the poles, so use real distances/areas and `areaWeightedMean` for global statistics. `getTopology(grid)` gives cached 8-neighbour tables and distances. Resolution is a parameter (UI offers 128×64, 256×128 default, 512×256). Never hard-code grid dimensions. The grid radius comes from `planetParams.radius`; nothing may assume Earth's radius. Per-cell constants tuned on the 128×64 reference grid must be scaled with `resolutionScale(grid)` or expressed in physical units (metres, m²) so behaviour does not change with resolution; verify by comparing 1 Gyr runs at two resolutions.
- **Determinism.** All randomness goes through `Rng` (`src/sim/core/rng.ts`), and its state is stored in `PlanetState.rngState`. The same seed must reproduce the same planet and history; don't use `Math.random()` inside `src/sim`.
- **Plain-data state.** `PlanetState` must stay serializable (typed arrays and plain objects, no class instances or closures), so it can be saved and moved into a Web Worker later.
- **Geosphere pipeline** (`src/sim/world.ts`): `generateTectonicPlanet` builds plates (noise-warped Voronoi with Euler-pole velocities), continental crust, boundary relief and the `upliftRate` field; each step then runs `plateDrift` → `tectonicUplift` → `flowRouting` (priority-flood depression filling + D8 + drainage area; runoff from the last step's precipitation via the Budyko curve, summed downstream into `discharge`) → `streamPowerEroder` (implicit Braun–Willett / Landlab FastscapeEroder, n = 1, driven by discharge / `REFERENCE_RUNOFF` as an effective area, so wet mountains erode faster than deserts) → `linearDiffuser` (finite-volume, land only, auto sub-stepping; slowed to 1 % on worlds with under 5 % ocean, `hillslopeWetness`, so dry planets keep their relief). Sea level is `SEA_LEVEL` = 0; ocean cells are flow outlets. Eroded material is removed, not deposited.
- **Plate drift** (`drift.ts`, `plates.ts`): each `Plate` stores its crust in its own reference raster (`plate.crust`, same grid as the planet) plus a cumulative `rotation` matrix. Each step the plates rotate and the planet fields (`plateId`, `elevation`, `crustType`) are re-composed by gathering from the rasters (plates are culled per cell by a bounding cap); before that, the previous step's field changes are written back as averaged deltas, because several planet cells can sample one reference cell. Crust created by hole filling never displaces another plate's crust, otherwise fill/consume cycles create runaway mountains. Never resample plate shapes from the planet grid — that is what made plates fragment in earlier attempts. Generation removes warped-Voronoi exclaves and places Euler poles about 90° from plate centroids for translation-like motion. Every 5 Myr of plate time, detached terranes below 200,000 km² (and all 1–3-cell specks) move between the plates' reference rasters, larger detached continents rift into stable new plate ids (at most four daughter slots), and undersized plates merge into their largest neighbour; reference-scale one-cell slivers enclosed by another plate are removed every 25 Myr. Overlaps: continental beats oceanic; same-type crust needs a clear depth/elevation advantage to displace the current owner; colliding continents thicken (spread over neighbours) and stall. Gaps become ridge-depth ocean floor split between the nearest bordering plates. Plates approaching a third of the globe stop annexing ambiguous overlaps and rift directly in their reference raster. Plate randomness has its own serialized `Rng` stream so outer step length does not change the plate-event sequence. Continental crust is kept near a target fraction by arc and shelf accretion; the target grows with age towards the crust needed for a 28 % mature land share (`continentalCrustTarget`: ~13% at 0.5 Gyr, ~30% by 2 Gyr), and plate speeds follow `mantleHeat` (≈1.8× today on a young planet), so young planets are island worlds with fast plates. If you change fields that belong to crust, make sure the write-back carries them into the plates.
- **Planets and stars** (`PlanetState.planetParams` in `src/sim/core/planet.ts`; `star.ts`; `src/sim/models/planetary.ts`): radius, surface gravity (default from Earth density, ∝ radius), orbital distance, star type G/K/M/F, rotation period (negative = retrograde), moon, tidal locking, initial water/N₂/CO₂, crustal carbon, tectonic regime and dynamo strength; omitted values inherit the Earth calibration. Star luminosity ∝ M⁴ with Gough's brightening scaled to the star's lifetime (`starProperties`); XUV and stellar wind ∝ luminosity/d² with an activity boost decaying over the star's active years (M 2 Gyr, K 0.5, others 0.1). Tidal locking is automatic for M stars at ≤ 0.2 AU: per-cell substellar insolation, no seasons, `LOCKED_HEAT_TRANSPORT`. Without a moon, obliquity random-walks deterministically (Laskar; fixed 10 Myr boundaries with their own seeded Rng, so step length does not matter), except slow rotators (> 1000 h) and locked planets. Presets may set `geosphere.fixedObliquity` to retain a documented present-day tilt during long calibration runs; Mars holds 25°. Mantle heat ∝ radius; the magnetic field fades as the core cools (lifetime ∝ radius⁴); `planetaryEvolution` records `magneticFieldLost`, `stagnantLid` and `atmosphereLost`. Tectonic regime is mobile or stagnant: mobile turns stagnant irreversibly when mantle heat drops below 0.7 or the ocean is lost; stagnant means no plate drift or uplift, plume volcanism only.
- **Climate** (`src/sim/models/atmosphere/`): `stellarEvolution` sets `globals.solarInput` from the planet age (faint young Sun; random planets start at 0.5, 2 or 4 Gyr, see Start options). `createClimate` is a 2D energy-balance model (Budyko–Sellers/North) on a coarse 64×32 grid with an ice–albedo feedback. Its low-temperature OLR keeps the calibrated North A + B·T fit, but a wet atmosphere bends smoothly towards the 294 W/m² Simpson–Nakajima limit above 40 °C; absorbed flux above the limit has no wet steady state, while a dry planet returns to linear OLR. Greenhouse forcing includes CO₂, CH₄ and explicit water vapour; CO₂/H₂O bands broaden as (surface pressure / Earth pressure)^0.5, with CO₂ counting only above 1 bar (its self-broadening below that is in the forcing fit), so an O₂-free young atmosphere needs ~0.5 bar CO₂; wet planets keep CO₂ below a 3-bar guardrail. Meridional diffusivity scales as pressure^0.7, and temperatures are bounded to −120…700 °C. The lapse rate scales with gravity; its datum is the sea surface only while the ocean covers ≥ 20 % of the planet, otherwise the area-mean surface. `THIN_ATMOSPHERE_COOLING` (40 W/m², faded in below 0.1 bar) removes the greenhouse built into the North OLR fit that a near-vacuum lacks (Mars lands near −60 °C). `heatTransportScale` = P^0.7 above 0.1 bar, linear in P below, floor 0.002, clamp 80, times a rotation scaling and `LOCKED_HEAT_TRANSPORT` (2.5) when locked. Below 0.1 bar, annual insolation contrast grows smoothly to 1.75× and seasonal land amplitude to 2.25× as pressure approaches zero; both return exactly 1 above the threshold, preserving Earth's numerical path. CO₂ frost uses albedo 0.65 (Leighton & Murray 1966) and frost-bearing winter surfaces are pinned to the pressure-dependent sublimation temperature inside the climate iteration. Hot dry CO₂ atmospheres get a sulfur-cloud/haze albedo (up to 0.75, Venus); clouds need water vapour (`CLOUD_VAPOR_SHARE`); runaway greenhouse needs water. In short steps temperatures approach equilibrium over `OCEAN_RESPONSE_TIME` (40 years). `globals.energyBalance` is a write-only breakdown of absorbed sunlight, outgoing longwave, greenhouse gases, reflective/aerosol cooling and runaway margin.
- **Atmosphere and water.** `atmosphere.co2` and `ch4` are partial pressures in microbar (the familiar Earth values remain numerically ppm); `n2`, inert gas and `waterVapor` are in bar, while `o2` remains a volume fraction and its partial pressure is derived. `globals.surfacePressure` is their total; bar↔column mass conversions use the planet's gravity. Condensed CO₂ is `globals.co2Ice` (global bar equivalent) plus the area-distributed `fields.co2Ice` local column. `co2FrostCycle` uses the James et al. (1992) fit `T = 3182.48 / (23.3494 − ln p[hPa])` (147.6 K at 6 mbar), the coldest-month diagnostic, a 1-year exponential exchange, and a 10 K annual-harmonic ablation margin; atmosphere + cap is conserved exactly, while carbon-cycle transfers continue to balance the crustal reservoir. With no existing cap it returns before any grid scan below 1000 microbar CO₂ or at/above 0.1 bar total pressure, making Earth bit-neutral and preventing collapse of the default 0.8-bar-N₂ locked world; thin CO₂-rich locked worlds can still collapse onto the nightside. `globals.water` is the conserved extant inventory in metres GEL; runaway steam escapes as hydrogen at an age/XUV- and cold-trap-dependent rate, escaped oxygen oxidises the crust, and `runawayGreenhouse` is reversible: the steam state rains out once the required OLR falls `RUNAWAY_RELEASE_HYSTERESIS` (8 W/m²) below the limit (`runawayEnded`), and `runawayMargin` arms a one-time `runawayWarning` within 15 W/m²; `oceansLost` is recorded once. Cold low-gravity worlds also lose hydrogen by Jeans-like escape (`JEANS_COLUMN_RATE`). Non-water gases are removed by stellar-wind sputtering (`SPUTTERING_RATE`, shielded by the magnetic field, scaled by wind and gravity), integrated exactly (constant above 1 bar, exponential below) so step length does not matter; inventories stay conserved and escaped amounts are recorded (`escapedAtmosphere`, `escapedWater`).
- **Seasons** (`src/sim/models/atmosphere/seasons.ts`): `controls.obliquity` sets axial tilt. The climate integrates daily-mean insolation over a circular orbit and diagnoses `seasonalAmplitude` from the analytic linear response of land or an ocean mixed layer to its first annual harmonic; land and ocean responses are mixed by continentality, 1 − exp(−distance to the sea / 1,000 km), so coasts stay maritime and interiors swing widely. `monthlyClimate` redistributes those annual diagnostics on demand for the inspector's Walter–Lieth diagram without changing state. Glaciers use positive degree days and seasonal snowfall, surface ice is weighted toward sunlit months, and biome treelines use warmest/coldest monthly means. This remains a steady-state diagnostic, not a time-stepped seasonal EBM.
- **Circulation and precipitation** (`circulation.ts`, `precipitation.ts`, on the shared 64×32 `atmosphereGrid`): a three-cell circulation (Hadley/Ferrel/polar) gives the surface wind fields `windU`/`windV`; the ITCZ follows the thermal equator column by column and the Hadley width grows with the equator–pole contrast and for slow rotators; beyond ~60° (blended from 45°) it becomes a single cell per hemisphere, and a retrograde rotation mirrors the zonal winds. The pressure map stays a 1013 hPa anomaly field (absolute pressure is `globals.surfacePressure`). Precipitation is a steady-state moisture budget carried by those winds (semi-Lagrangian, 150 pseudo-steps): evaporation from the sea towards a Clausius–Clapeyron humidity, recycling over land (more with plants), rain rate raised by converging and upslope air and lowered by sinking air, plus rain-out above saturation; the coarse result is shifted towards fine windward slopes within each coarse cell. Calibrate with zonal means (ITCZ wet, subtropics dry, mid-latitudes wetter, poles dry) and the desert share of land, at two resolutions.
- **Ocean** (`ocean.ts`, same atmosphere grid): wind-driven gyres after Stommel — Sverdrup interior integrated westward from each basin's east coast, closed by a western boundary layer; basins that nearly circle the planet lose their gyres (circumpolar flow); a small zonal wind drift. Ekman divergence gives upwelling (equator, eastern coasts). The sea surface anomaly (`oceanAnomaly`) = currents across the zonal-mean temperature gradient of the background state (climate temperature minus last anomaly, so it cannot feed on itself and drift) + upwelling cooling, net heat removed, faded towards the poles, spilled onto coasts; the climate adds it to temperatures (so cold currents also dry coasts through lower evaporation).
- **Carbon cycle** (`carbon.ts`): the silicate-weathering thermostat. Outgassing is the area-weighted integral of `volcanicActivity` times mantle heat and the volcanism control; the activity field is normalized to retain the modern 30% hotspot / 70% plate-speed calibration. Organic carbon burial (`MODERN_BURIAL`, 20% of the flux for a modern biosphere, scaled by photosynthesis) is an extra sink; seafloor weathering (`SEAFLOOR_SHARE` 8%) gives water worlds a thermostat, and below 22 % land an extra, strongly temperature-dependent seafloor term (`MAX_LOW_LAND_SEAFLOOR_BOOST`, 0.1/°C) keeps warm low-land young worlds from running away without chilling cold ones; land weathering grows with runoff, temperature (≈9%/°C) and CO₂ and stops under ice. Both weathering sinks stop without liquid water, after which outgassing can build CO₂ through the full 100-bar representable range (`MAX_CO2 = 1e8` microbar). CO₂ is solved implicitly each step, predicting the warming at each candidate CO₂ from `greenhouseForcing` (a fixed sensitivity underestimated thick CO₂, and the one-step climate lag then overshot in bar-sized swings into a runaway); wet worlds retain the former 1-bar natural solve guardrail so raising the representable maximum does not change Earth calibration. Outgassing draws on a finite crustal carbon reservoir (`globals.crustalCarbon`, default 80 bar × (g/g⊕)²): dry or sinkless worlds degas it first-order over `DRY_DEGASSING_TIME` (300 Myr) and the wet solve is booked against it. `globals.carbonBudget` is write-only diagnostics in µbar/yr and Gt C/yr; its realized natural decomposition, civilization, clathrate and device terms sum exactly to `net` and must never feed back into the solve. `createRandomWorld` spins the atmosphere up before the first step (`spinUpAtmosphere` damps CO₂ updates in log space when the first guess is a snowball). Expected behaviour: CO₂ falls as the star brightens, then a runaway begins near 7 Gyr and ocean loss leaves a hot, dry, CO₂-rich planet.
- **Volcanism** (`volcanism.ts`): `volcanicActivity` combines convergent arcs, divergent ridges and continental rifts with 10–20 long-lived mantle-frame hotspots. Hotspots build moving-plate island chains in metres/year while old oceanic edifices subside. Seeded eruption rates are per year; geological steps aggregate ordinary activity, short steps resolve transient one-year aerosol forcing (`globals.volcanicAerosol` is the step-mean forcing, `volcanicAerosolEnd` the carried end value, both exact integrals of the 1.5-year decay), and rare large igneous provinces add an extra outgassing flux (`globals.lipOutgassing`, 1.5× modern) for about 1 Myr — a flux, not a CO₂ pulse, so the implicit carbon solve answers it the same at any step length (+2–5 °C) — and record a located event.
- **Impacts and start options** (`impacts.ts`, `PLANET_STARTS` in `world.ts`): a late heavy bombardment, Poisson impacts per step from a flux decaying over 150 Myr plus a small background, with power-law sizes; craters go through the drift write-back, comets add a little water, big impacts heat the climate briefly (`globals.impactHeating`) and sterilise life locally or, early on, globally. New random planets start **young** (0.5 Gyr, no life, CO₂-rich, few continents), **microbial** (2 Gyr, prokaryotes) or **quick** (4 Gyr, the pre-M11 pace via `evolutionTimeFactors`); the choice is part of the saved `RandomWorldSettings`. A young start's geological era lasts several hundred 2 Myr steps.
- **Surface albedo and life.** `createSurfaceAlbedo` sets the ice-free `surfaceAlbedo` field (ocean, land, daisies); the climate model mixes it with ice. Biosphere components change albedo through the fields this component reads.
- **Biomes** (`src/sim/models/biosphere/biomes.ts`, data in `src/sim/data/biomes.ts`): a Whittaker-style classification from annual temperature and precipitation, plus ice, alpine rock and river swamps. Biome data sets surface albedo and a weathering multiplier, so vegetation feeds back on climate and CO₂. Tune biome properties in the data table, not in the models.
- **Sea level, aridity and lakes.** `globals.seaLevel` is found by bisection over the real-area elevation field so basin volume equals liquid `globals.water` after subtracting grounded land ice and atmospheric vapour (10 kyr relaxation). Generated planets initialize the inventory to reproduce the 0 m ice-free datum; a uniform `seaLevelDatum` re-referencing prevents plate-raster resampling from moving that arbitrary datum, without changing relief or capacity. Low-water worlds fill only their deepest basins and zero liquid water yields no ocean cells. Land vs ocean is always tested against `globals.seaLevel`. Biomes use P/PET aridity; significant closed depressions hold freshwater or endorheic salt lakes/flats and terminate the river network.
- **Glaciers, sediments and clouds.** Land ice is `iceThickness` from a snow mass balance (snowfall − melt − sublimation, exponential approach to a sheet thickness set by the ice extent; `ice.ts`); land `iceCover` = glacier cover from thickness plus snow cover on the thermal ramp limited by snowfall, so polar deserts can stay bare; sea ice stays thermal. The stream power eroder adds warm-based glacial erosion (fjords to 500 m below sea level) and routes the eroded volume downstream: deposition where carrying capacity (C·Q·S) falls short, filled depressions, then shelf/delta deposits within ~500 km of the mouth (mass conserved; any remainder in `globals.sedimentExport`). Land ice is limited by the water inventory (`limitIceToInventory`), and cold-trapped ice is kept without a sea. `cloudModel` (`clouds.ts`) diagnoses high cloud from rain and low cloud from cold seas / land humidity; the climate adds `LOW_CLOUD_ALBEDO` × (low cloud − `REFERENCE_LOW_CLOUD`) to the albedo of planets that run it (Earth-like mean total cover ≈ 0.6).
- **Life** (`src/sim/models/biosphere/life.ts`, classes in `src/sim/data/lifeClasses.ts`): `PlanetState.biota.populations` holds a population (0..1 of carrying capacity) per class per cell. Each step populations relax to their suitability (habitat, temperature, O₂, plants for land animals) where present, and colonise adjacent habitable cells at `DISPERSAL_SPEED` (300 km/Myr) through the shared `disperse` front model (`src/sim/models/dispersal.ts`), so spreading does not depend on the step length or the grid and life cannot cross unsuitable terrain. Missing classes evolve from a living ancestor at a rate set by how much of their potential habitat the ancestor occupies (`BASE_EVOLUTION_TIME`, `difficulty`), counted only on the frontier next to the ancestor's habitat (the coast for a move between sea and land), so the share does not shrink with cell size; abiogenesis and each class keep a seeded exponential hazard threshold in `biota.ecology`, so changing the geological step does not reroll their timing. Plants (`vegetation` field) green the biomes and speed weathering. `biogeochemistry` derives O₂ from photosynthesis (with a sink that makes a Great Oxidation Event; the sink is large on a young, reduced planet and fades with age, `oxygenSink`, so oxidation comes at ~2.3–2.5 Gyr) and CH₄ from anoxic microbes. Per-class `evolutionTime` multipliers (data) make the first steps slow: eukaryotes ~1–1.5 Gyr, plants ~0.7 Gyr, radiates ~1.2 Gyr, later classes at the base pace; Quick starts cap the acceleration of those exceptional transitions instead of erasing their wait. On a lifeless planet prokaryotes arise by chance (abiogenesis) in liquid, ice-free sea near volcanic vents, suppressed after big impacts, and can arise again after a sterilisation.
- **Turning points of life (M13, first pass).** Drivers: `dust.ts` (impacts, LIPs and nuclear war load fine dust, sulfate and soot reservoirs with 0.3/1.5/4-year fallout; `globals.dust` is the step-mean optical depth for climate forcing 40·(1 − e^−τ) W/m², while life uses the optical depth integrated since its previous 10 kyr update), `oceanChemistry.ts` (phosphate `nutrients` from weathering, rivers, shelves and Ekman `upwelling` with a 30 kyr residence; `oceanOxygen` from pO₂, temperature and respiration; `globals.oceanAcidity` from CO₂ rising faster than a 10 kyr buffered reference), `clathrates.ts` (cold land and shelves store methane up to ~7,000 Gt C; rapid warming against a 10 kyr reference releases CH₄ that oxidises to CO₂). In `life.ts`: light exp(−dust) through the food chain, per-class `minOceanOxygen`, nutrient-limited marine capacity, calcifiers hurt by acidity, wildfires above 25 % O₂, C4 plants starve below ~10 µbar CO₂ (full growth from 100), complex life stressed when temperature outruns a 100 kyr adapted reference; declines take 50 kyr, growth 2 Myr. Biodiversity = exp(Shannon entropy of class cover)/15. A mass extinction (complex biomass < 40 % of its recent peak) records its main cause and opens an 8 Myr recovery boost; animals need ≥ 0.04 bar O₂ and radiate after a snowball (`cambrianExplosion`); classes of one guild share capacity with a 25 % edge for the more advanced. Sentience uses the occupied geographic share of a class's habitat, rather than its guild-reduced biomass, and has its own serialized hazard threshold. Dust reservoirs, pending sources and ecological memory are typed plain-data state initialized in `createPlanet` and hydrated for older saves.
- **Civilization** (`src/sim/models/civilization/`, ages and energy data in `src/sim/data/civilization.ts`): established animals may become sentient (weighted by `SENTIENCE_POTENTIAL` and the geographic share of their physical habitat they occupy). The four marine candidates share only 0.022 potential: they are established hundreds of Myr before land vertebrates, so marine intelligence stays rare (a route for planets whose land life never establishes); mammals are the likeliest class, then reptiles and birds. The civilization settles where its species lives and food allows, spreads at its age's `spreadSpeed` through `disperse`, and crosses ocean passages within the age's physical `seaCrossingReach` (Stone 0, Bronze 300 km, Iron 800 km, Industrial 3,000 km, Atomic 6,000 km, Information 10,000 km, Nanotech 20,000 km); both speed and reach use real distances so spreading stays independent of step length and resolution. It advances through `TECH_AGES`; technology pace scales with `(population / expectedPopulation)^0.35`, clamped to 0.25–2. Finishing Nanotech launches Exodus only at a population of at least 1 billion; below that threshold progress stays at 1 while ordinary growth and hazards continue. `cities.ts` derives persistent named cities from physically spaced settlement maxima, assigns their share of the settled population, retains short-lived ruins and keeps the largest as the capital without drawing simulation RNG. Saved `civPolicy` percentages choose an age-unlocked energy mix and science/agriculture/medicine/philosophy/culture investment. Energy output drives growth and technology; biomass clears more vegetation, fossil output draws the finite `globals.fossilCarbon` reserve and sends its Gt C pulse through the greenhouse-predicting carbon solve, and nuclear share raises war risk. Organic burial forms the reserve with a 300 Myr geological loss time. `globals.pollution` integrates industrial sources with exact 50-year decay and mildly stresses civilization and complex life at settlements. A sub-linear environmental-population scale makes island societies visible while remaining exactly linear at and above 7 billion people. Plague/war hazards use serialized threshold progress so short and long civilization steps agree. `PlanetState.events` logs notable moments (`recordEvent`).
- **Eras and time scales** (`src/sim/eras.ts`, after SimEarth): `planetEra` is geological while only microbes live (2 Myr steps, so drifting plates move only a cell or two per frame), evolution once complex life exists (500 kyr), civilization from sentience and technology from the Industrial Age (the age's `yearsPerStep`, down to 5 years); after an Exodus or collapse it falls back to evolution. `World.stepYears` is `eraStepYears`; `eraTracker` stores `globals.era` and logs `eraReached`. Every model must therefore give the same results whatever the step length: use rates × dt, exponential relaxation or implicit solves, never "one cell per step". Slow components are wrapped with `withMinInterval` (geology 100 kyr, evolution 10 kyr, history 1 Myr) so they cost nothing in short steps; components receive the elapsed time as `dt`. Saved adaptive pacing batches up to eight unchanged physics steps into one Fast-speed worker frame after quiet ticks, but returns to one immediately on events or input and checks auto-pause between every step.
- **Feedback and alerts.** `eventMetadata.ts` is the exhaustive importance table for every `EventKey`; the UI turns important events into coalesced, accessible toasts, while `SimHost` applies locally stored auto-pause choices before scheduling another step. `trendAlerts.ts` owns all trend/milestone thresholds and saved hysteresis memory; it draws no RNG and may change only diagnostic memory and the event log.
- **Player controls and tools.** `PlanetState.controls` holds player-set targets while `effectiveControls` approaches them with an exact exponential era-scaled lag; target movement costs Ω according to `MODEL_CONTROL_COSTS` and remains free with `unlimitedEnergy`. Tools (`src/sim/tools/tools.ts`) are pure functions on the state, with all prices and intended uses in `TOOLS`; normal energy starts at 350, caps at 2000 and earns era-scaled income, while saved difficulty multiplies income/cap, weathering, disasters and goal tolerance. Terrain edits reach the plates through the drift write-back.
- **Save files** (`src/sim/serialize.ts`): the whole `PlanetState` plus scenario id, as a binary file (magic, `SAVE_VERSION`, JSON header with typed arrays referenced into an aligned data section), gzip-compressed in the worker. Anything added to `PlanetState` is saved automatically if it is plain data or a supported typed array; bump `SAVE_VERSION` when the shape changes incompatibly. Each scenario provides `restore(planet)` that rebuilds its simulation without regenerating; component schedules live in `PlanetState.lastRunYear` so a loaded game resumes identically.
- **Scenarios** (`src/sim/scenarios/`): `SCENARIOS` maps ids to world factories (`random` = `createRandomWorld`, `daisyworld`, `aquarium` = a random planet with no continents, `cambrian` = a goal-free quick world at 4 Gyr with 15 % O₂ and sea animals up to trichordates but no land plants, `mars` and `venus` = `createPlanetPreset`: present day 4.5 Gyr, stagnant lid, no magnetic field). Mars begins with 5.9 mbar atmospheric CO₂, 5.9 mbar-equivalent cap/buried CO₂ ice, and 0.0441 bar in the remaining crustal reservoir (0.0559 bar accessible carbon total); the preset keeps its present 25° obliquity fixed for reproducible long calibration runs. Custom planet parameters are chosen in the new-planet menu, and the Planet panel (`PlanetPanel.tsx`) shows them. Each `World` carries its own `yearsPerStep`. Daisyworld is land-only with no geology or carbon cycle and no ice–albedo feedback; daisies (Watson & Lovelock 1983) run many generations per step, relax towards the result and disperse to neighbours. The UI picks charts and the initial map layer per scenario (`SCENARIO_VIEW` in `App.tsx`).
- **Goals** (`src/sim/goals/`): goal state is plain saved data on `PlanetState`; the final `goalTracker` component evaluates objectives in absolute simulated years, records one `goalWon`/`goalLost` event and freezes the outcome and score. Goal definitions also supply the UI checklist and optional authoritative control ranges, clamped in `SimHost`. Goal scenarios must restore through a pipeline whose last component is the tracker. Scenarios that place established life (`seedEstablishedComplexLife`) first oxygenate the world and run four 500 kyr steps (`settleClimate`), so the methane loss and regional climate settle, and set the ecology's adapted temperature before seeding. The Exodus goal (`stoneAge`: mammals made sentient on an 8·10¹²–4.5·10¹³ m² homeland with normal water inventory and a 2,000 km initial settlement radius, won by the `exodus` event after reaching the 1-billion population floor, lost by a collapse or after 73 kyr on normal) and the Terraform Mars goal (`terraformGoal`; a Venus goal awaits a slow-rotator climate calibration) need pressure, mean temperature, ≥ 2 % open sea and land plants held for 10 Myr. Brightening Sun survives to 8.5 Gyr on normal, caps its score at 1000 and loses on runaway, ocean loss or complex-life extinction; saved difficulty scales deadlines through goal tolerance. **Devices** (`src/sim/tools/devices.ts`, `PlanetState.devices`, one per cell) are built with tools and run every step in `terraformDevices` (before the clathrates): gas rates are bar/yr on an Earth-sized planet scaled by `gasScale` (∝ g/R²), CO₂ scrubbers stop at 280 µbar, the biome factory sows plants within 900 km; impacts, large eruptions, LIPs and the meteor/volcano/ice-meteor tools destroy devices nearby (`destroyDevicesNear`). The ice meteor adds 5·10¹⁸ kg of water. `biosignature` (O₂ with CH₄ = detected, one alone = possible) is shown in the vitals.
- **History** (`src/sim/history.ts`): `recordHistory` samples global series each step into `PlanetState.history` (thinned past 2000 samples), including carbon outgassing, weathering, burial and net rates; frames carry it to the small-multiple uPlot charts (`src/ui/charts`). One measure per chart — no dual axes. Charts use adaptive planet-age units, per-measure linear/log scales, synchronized hover readouts, era bands and scenario-specific selections stored locally.
- **Tuning.** Erodibility and uplift are effective values for ~300 km cells, not field measurements, and are tuned as a pair: their ratio sets equilibrium mountain height, their magnitude sets how fast landscapes evolve. Check changes over ~1 Gyr of 1 Myr steps (land fraction, mean land elevation, peak height), not just one step.
- **UI layout** (`src/ui`): `TopBar` (time controls, vital signs, planet menu), a left sidebar with the tools `Collapsible` and launchers for floating Geosphere, Atmosphere, Biosphere and Planet windows, the stage (`LayerBar`, `PlanetView` = flat map or optional globe with the cell inspector, `MapLegend`) and a right `TabbedPanel` (history, life, civilization). Floating windows are draggable and persistent on desktop, and become one-at-a-time bottom sheets below 700 px. English and Czech UI strings live in `src/i18n`; Settings offers Auto/English/Čeština and a language change reloads the page. Keep labels able to wrap in the desktop and below-700 px layouts. `SCENARIO_VIEW` in `App.tsx` sets each scenario's layers and charts; keyboard shortcuts live in `App.tsx` via `useShortcuts`. Every control gets a `title` hint from the strings. The first-game tour uses the shared anchor registry in `guide.ts`; Help contains linked model pages and a searchable glossary, and panel `?` buttons open the matching page. UI icons are inline SVG in `icons.tsx` (currentColor); the app icon is in `public/`. The flat map zooms (wheel, +/−, buttons; `render/viewport.ts`, drawn at screen resolution from a 1-pixel-per-cell source canvas) and pans by dragging; `Minimap.tsx` shows the whole planet with the view marked (M toggles it). Wind and current overlays (`OVERLAYS` in `PlanetView.tsx`) are animated particles in latitude/longitude (`render/particles.ts`, windy.com style) drawn through the map or globe projection on a screen-resolution canvas; with prefers-reduced-motion they fall back to static arrows (`render/arrows.ts`). The ambient canvas caches sparse frame-driven pixel details and becomes a still composition under reduced motion.
  Zoomed terrain, biome and seafloor cells fade to cached, original 16×16 pixel-art tiles above about 10 screen pixels per cell; frameless biome/terrain tiles join without a grid, seafloor motifs retain data colours, and the globe and quantitative layers keep the flat palette rendering.
- **Dialogs and menus** (`src/ui/Dialog.tsx`): modal flows share one focus-trapping, focus-restoring dialog that becomes a full-screen sheet below 700 px. New Planet uses scenario/start cards and preserves the worker's random-world settings; Save/Load, Help/About and goal outcomes use the same shell.
- **Map symbols.** Life, cities, devices and located events use original cached 16×16 sprites from `render/pixelIcons.ts`, painted at integer scale with colour-vision-safe palettes on the static overlay canvas; the 24-unit SVG/`Path2D` art in `render/mapIcons.ts` remains for UI legends and the event log. The `icons` overlay (key I) draws the longitude/latitude-anchored life lattice plus discrete population-tiered city markers at constant screen size; capitals and ruins are distinct and smaller cities appear as the map zooms in. `PlanetEvent.cell` locates events; the log centres the map on them. More overlays: `ambient` (persisted, procedural water, clouds, volcanoes, night lights and wildlife from rendered fields), `mantle` (T, plate-motion arrows from Euler poles plus hotspots, `render/mantleFlow.ts`), `names` (N, collision-avoiding labels for cities and features from `src/sim/mapNames.ts`: pronounceable names hashed from the seed and a private ordinal, never the simulation RNG; `mapNamingModel` re-labels every geology interval and keeps a name by footprint overlap, the larger part of a split keeps it; saved in `PlanetState.mapNaming`) and `events` (V, every located event in the log, filterable by category); the `seafloor` layer drains the ocean to show bathymetry.
  Zoomed terrain sprites in `render/terrainSprites.ts` are original, frameless 16×16 character grids with 2–4 variants, chosen by a stable cell hash and cached by surface, variant and integer screen size; water advances every 0.5 s unless reduced motion is enabled, and tiles never use simulation RNG.
- **Worker.** The simulation runs in a Web Worker (`src/worker/sim.worker.ts` → `SimHost`). The UI sends `WorkerRequest`s and receives `Frame`s: transferred copies of the fields in `RENDERED_FIELDS` plus stats. A field the map needs must be added to `RENDERED_FIELDS`.
- **Performance.** `simulation.timings` gives per-component milliseconds for the last step (shown as "Step: N ms" in the UI). Measure before optimizing. Approximate step costs on a young planet (this dev machine, M18b): 128×64 ≈ 100 ms, 256×128 ≈ 270 ms, 512×256 ≈ 1 s; climate (the coarse conjugate-gradient solve and the fine albedo iteration) and `plateDrift` dominate. Optimisations must keep results bit-identical: `src/sim/determinism.test.ts` holds 64×32 digests of young, quick and Stone age runs. The digests depend on the V8 version (Node 22 differs from 24+ in Math rounding), so CI and `.nvmrc` pin Node 24. The worker sends only the fields the visible layer, overlays and inspector need (`view` request; the UI merges partial frames) and skips frames while the UI has not acknowledged the last one. The life model only works on classes that exist or can evolve, and the carbon cycle sums weathering once per step — keep hot loops away from absent classes and per-iteration planet sweeps.
- **Natural disasters** (`models/disasters.ts`): saved switches gate earthquakes, tsunamis, cyclones, droughts, dust storms, impacts and supervolcanoes; annual hazard rates damage civilization (never terrain or biota), drought lowers food capacity, dust uses the aerosol model, notable events use a separate serialized RNG, and only the directed earthquake tool uplifts terrain.

## Roadmap

M0 scaffold (done) → M1 geosphere (done: plate-based terrain, drift, uplift, flow routing, fluvial erosion, diffusion; deliberately not doing more Landlab-style physics such as flexure or sediment transport until gameplay needs it) → M2 climate (done: energy balance, ice–albedo, precipitation, carbon cycle, history charts, Daisyworld) → M3 biomes (done) → M4 life classes and evolution (done) → M5 civilization (done) → M6 player tools, Ω energy budget, scenarios (done: tools, controls, save/load) → M7 presentation (done = alpha 0.1, tag v0.1.0-alpha: optional globe view `src/render/globe.ts`, CI and GitHub Pages workflows in `.github/workflows`, README with a single milestone table — keep it up to date). Roadmap (detailed in README; physical core first, game layers once it is tuned): M8 interface (done = alpha 0.2) → M9 Earth system (done: eras, circulation, ocean, glaciers, clouds, seasons) → M10 plates and volcanism (done) → M11 young planet (done: origin of life, bombardment, growing continents) → M12 atmosphere and planets (done: M12a pressure, water vapour, runaway greenhouse, water inventory; M12b planet parameters, stars, rotation, tidal locking, magnetic field, escape, stagnant lid, Mars/Venus presets) → M13 turning points of life (Cambrian explosion, mass extinctions) → M14 goals (Mars, snowball and Brightening Sun scenarios; the last keeps oceans past the ~7 Gyr runaway; Terraform Venus is an add-on after the public beta) → M15 challenge → M16 graphics (icons for events, tools, layers and charts; better charts; menus; Walter–Lieth climate diagrams; life and city icon overlays on the map) → M17 feedback → M18 onboarding and balance → M19 sound and comfort (music, autosave and settings, sharing, export, touch and accessibility, Czech translation) → M20 public beta (stability, playtests, save compatibility); each milestone is a minor release.
